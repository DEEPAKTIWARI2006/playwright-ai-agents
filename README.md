# Playwright AI Agents

> **Automating Playwright test creation and maintenance with LLM‑driven agents**

This repository contains three Python agents that together form an end‑to‑end pipeline for generating, running, and healing Playwright tests using Large Language Models (LLMs) via the Playwright **MCP (Model‑Centric‑Programming) tools**.

| Agent | Primary purpose | LLM used (default) |
|------|----------------|--------------------|
| `planner_agent.py` | Reads a requirements specification (DOCX) and, using Playwright MCP browser tools, **explores** the target application to produce a **Markdown test plan** and a **JSON test‑case list**. | `gpt-oss:120b-cloud` (configurable via `.env`) |
| `generator_agent.py` | Consumes the plan & test‑case JSON, prompts the LLM to **generate a stand‑alone TypeScript Playwright test file** for each case. Files are emitted to `generated-tests/`. | `gemma4:31b‑cloud` (hard‑coded) |
| `healer_agent.py` | Reads Playwright’s `results.json` after a test run, extracts failing tests, and uses an LLM to **fix** each failure. Healed files are written to `healed-tests/` (original sources remain untouched). | `gpt-oss:120b-cloud` (hard‑coded) |

The agents are driven by **skill files** under `playwright-mcp-skills/` that embed system prompts, tool lists, and model selection for each stage:

* `playwright-test-planner.agent.md`
* `playwright-test-generator.agent.md`
* `playwright-test-healer.agent.md`

## Prerequisites

| Requirement | Why it’s needed | Install / Verify |
|-------------|----------------|-----------------|
| **Python 3.10+** | Core agents are Python scripts | `python --version` |
| **Node.js >= 18** | Playwright CLI & MCP server | `node --version` |
| **Playwright** (npm dev dependency) | Browser automation & MCP server | `npm i -D @playwright/test @playwright/mcp` |
| **Ollama** (optional) | Local LLM serving (e.g., `gemma`) | Follow <https://ollama.com> |
| **Cloud LLM credentials** (Gemma 4, Claude Sonnet 4, etc.) | Agents reference remote models | No extra install – the model name is passed to `OllamaLLM` / `ChatOllama` |
| **Python packages** | `python-docx`, `python-dotenv`, `mcp`, `langchain`, `langchain‑ollama` | See **Setup** below |
| **Requirements DOCX** | Source of functional specifications | Provided under `requirements/` |

> The repository already ships a virtual‑environment folder (`.venv/`) for quick testing, but you can create your own environment if preferred.

## Setup & Installation

```powershell
# 1️⃣ Clone the repo (if you haven't already)
git clone <repo‑url> C:\Basefolder\AI\playwright-ai-agents
cd C:\Basefolder\AI\playwright-ai-agents

# 2️⃣ Create a fresh Python venv (optional but recommended)
python -m venv .venv
.\.venv\Scripts\activate

# 3️⃣ Install Python dependencies
pip install python-docx python-dotenv mcp langchain langchain-ollama

# 4️⃣ Install Playwright and its MCP adapter
npm i -D @playwright/test @playwright/mcp

# 5️⃣ Install browsers (Playwright step)
npx playwright install
```

> If you already have a `.venv/` directory you can simply activate it and run `pip install -r requirements.txt` (you may need to create a `requirements.txt` containing the packages listed above).

### Sample `.env`

Create a `.env` file in the project root (the repo already contains one you can copy/adjust):

```dotenv
# LLM configuration for the Planner
PLANNER_MODEL_NAME=gpt-oss:120b-cloud
PLANNER_MAX_EXPLORATION_ACTIONS=25
PLANNER_BASE_URL=https://www.saucedemo.com/

# Paths – relative to the project root
PLANNER_MCP_CONFIG_FILE=playwright_mcp_config.json
PLANNER_REQUIREMENTS_FILE=requirements/SauceDemo_Requirements_Specification.docx
PLANNER_INSTRUCTIONS_FILE=playwright-mcp-skills/playwright-test-planner.agent.md

# Output locations
PLANNER_ARTIFACTS_DIR=artifacts
PLANNER_TEST_PLAN_OUTPUT_FILE=artifacts/test_plan.md
PLANNER_TEST_CASES_OUTPUT_FILE=artifacts/test_cases.json
PLANNER_RAW_RESPONSE_OUTPUT_FILE=artifacts/test_generation_raw_response.txt
```

> The generator and healer agents are hard‑coded to use the **Gemma 4** and **GPT‑OSS 120B** models respectively. If you wish to change them, edit the `model=` argument in the corresponding Python file.

## Configuration

| File | Purpose |
|------|---------|
| `playwright_mcp_config.json` | Defines how the MCP server is started (`npx @playwright/mcp@latest`). The `command` and `args` are consumed by the agents when creating a `StdioServerParameters` object. |
| `.env` | Supplies environment‑specific values (model names, base URL, file locations). The planner reads these with `python-dotenv`. |
| `playwright-mcp-skills/*.agent.md` | System prompts, tool lists, and model selection for each agent. Editing them changes the *behaviour* of the underlying LLM without touching code. |
| `requirements/*.docx` | The source requirements specification (DOCX). The planner extracts plain‑text paragraphs & tables from this file. |

**Tip:** After editing any of the skill markdown files you **must** re‑run the relevant agent so the new prompt is loaded.

## Running the Pipeline

Below is the **canonical workflow**. Each step can be executed independently; the output of one feeds the next.

### 1️⃣ Run the Planner

```powershell
python planner_agent.py
```

*What happens*

* Loads the DOCX and (optionally) the planner skill file.  
* Starts a Playwright MCP server (`npx playwright run-test-mcp-server`).  
* Opens the target URL (`PLANNER_BASE_URL`).  
* Uses browser tools (`browser_navigate`, `browser_snapshot`, etc.) to **explore** the UI while preserving requirement IDs.  
* After exploration finishes (or after `MAX_EXPLORATION_ACTIONS`) the LLM produces a **Markdown test plan** (`artifacts/test_plan.md`) and a **JSON test‑case list** (`artifacts/test_cases.json`).  
* Raw LLM response is saved to `artifacts/test_generation_raw_response.txt`.

> **Artifacts** are stored under `artifacts/`. You can inspect them before moving forward.

### 2️⃣ Run the Generator

```powershell
python generator_agent.py
```

*What happens*

* Reads the plan, test‑case JSON, generator skill file, and MCP config.  
* Starts a fresh MCP server session for **snapshotting** the page once (used for locator hints).  
* For each test case it builds a custom prompt containing the plan, the case JSON, the snapshot, and the generator instructions.  
* The LLM returns **only the final TypeScript source code** (code fences are stripped).  
* Each file is written to `generated-tests/` with a slugified name derived from the test title.  
* If a file would clash, it is prefixed with the case index (`01‑…`).

You should now have a set of `*.spec.ts` files ready for Playwright.

### 3️⃣ Run Playwright Tests

The project assumes you have a **`tests/`** directory containing any seed or hand‑written tests. The generated files need to be copied there before execution.

```powershell
# Manual copy – adjust if you prefer an automated script
xcopy /E /I generated-tests\* tests\

# Execute the full suite
npx playwright test
```

*Result* – Playwright writes its JSON report to `test-results/results.json` and an HTML report to `playwright-report/index.html`.  

> **Tip:** You can add a short npm script to the `package.json` if you run this pipeline often, e.g.:

```json
"scripts": {
  "run-tests": "npx playwright test",
  "plan": "python planner_agent.py",
  "gen": "python generator_agent.py",
  "heal": "python healer_agent.py"
}
```

### 4️⃣ Run the Healer (after a failing run)

```powershell
python healer_agent.py
```

*What happens*

* Reads `test-results/results.json` (fails fast if the file is missing).  
* Writes a consolidated `artifacts/failure-context.json` that contains the JSON report, HTML report location, and a copy of each failure record.  
* Takes a **snapshot of the `test-results/` and `playwright-report/` folders** so that any MCP tool that accidentally overwrites them can be restored after each healing attempt.  
* For each *unique* failing test it launches a **LangChain‑based agent** (`ChatOllama` with `gpt-oss:120b-cloud`) that:  
  * Reads the original source file (using the built‑in `read_project_file` tool).  
  * Runs `test_debug` and other MCP debugging tools to gather context.  
  * Generates a **healed version** of the test source.  
  * Writes the healed copy to `healed-tests/\<same‑relative‑path\>.ts` while **leaving the original file untouched**.  
* After each healing run the original `test-results/` and `playwright-report/` directories are **restored** from the snapshot, protecting subsequent iterations.

You can now re‑run `npx playwright test` (pointing to the `healed-tests/` directory or copying those files over `tests/`) to verify that the failures have been resolved.

## Customization Guidance

| What you want to change | Where to edit |
|------------------------|----------------|
| **Change the target web app** | Update `PLANNER_BASE_URL` in `.env` (or set `BASE_URL` inside `planner_agent.py`). |
| **Swap LLM models** | - Planner: edit `MODEL_NAME` after loading `.env` (`PLANNER_MODEL_NAME`). <br> - Generator: modify line `llm = OllamaLLM(model="gemma4:31b-cloud")` in `generator_agent.py`. <br> - Healer: modify `MODEL_NAME = "gpt-oss:120b-cloud"` in `healer_agent.py`. |
| **Alter the exploration depth** | Change `PLANNER_MAX_EXPLORATION_ACTIONS` (default 25). |
| **Add or remove MCP tools** | Edit the `tools:` section of the corresponding `*.agent.md` skill file. |
| **Modify output locations** | Adjust the path constants (`ARTIFACTS_DIR`, `OUTPUT_DIR`, etc.) in the Python scripts. |
| **Tune prompt wording** | The three skill markdown files contain the full system prompts. Adding a “(Recommended)” label to a bullet list inside those files will affect the LLM’s behaviour. |

> **Safety tip:** The healer deliberately never writes into `test-results/` or `playwright-report/`. If you add a new tool that writes files, make sure it respects the same guard logic (or add it to `PRESERVED_DIRS`).

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| **Planner crashes with `FileNotFoundError: Requirements document not found`** | Wrong path or missing DOCX. | Verify `PLANNER_REQUIREMENTS_FILE` in `.env` points to `requirements/...`. |
| **LLM returns non‑JSON for the test plan** | Model changed output format (e.g., added Markdown fences). | Open `planner_agent.py` → `parse_json_response()` strips fences; ensure the LLM still returns a JSON object. |
| **Generator produces empty files** | `generator_agent.py` could not locate the snapshot file, or the prompt got truncated. | Check `artifacts/generator_page_snapshot.txt` exists and is non‑empty. |
| **Healer reports “Original test file not found”** | The failure report uses a relative path that does not map to `tests/` or `generated-tests/`. | Verify the Playwright run was executed from the project root and that the test files exist at those locations. |
| **MCP server fails to start (`command not found: npx`)** | Node / npm not in PATH. | Ensure Node.js is installed and `npx` is reachable from the command line. |
| **Model connection errors (e.g., “cannot locate model gemma4”)** | Ollama server not running or wrong model name. | Start Ollama (`ollama serve`) and pull the model (`ollama pull gemma4:31b`). |
| **Healer times out (180 s)** | Complex failure or missing artifacts make debugging expensive. | Increase `HEALER_TIMEOUT_SECONDS` in `healer_agent.py` or run the healer on a single failure at a time. |
| **PermissionError when writing to `generated-tests/`** | The directory is read‑only or you lack file‑system rights. | Ensure the user running the scripts has write permission to the project folder. |

When you encounter an unexpected exception, the stack trace printed by the agent (or by Python) usually points to the line that failed. The agents deliberately surround remote calls with `try/except` blocks that surface a concise error message.
